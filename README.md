# Võ Quang Triều — Portfolio

Personal portfolio built from public GitHub data for [@QTrieu0610](https://github.com/QTrieu0610).
React + TypeScript + Vite + Tailwind CSS v4. No runtime dependencies beyond React.

![Desktop screenshot](docs/screenshots/desktop.png)

## Run locally

```bash
npm install
npm run dev          # http://localhost:5173
npm run check        # typecheck + lint + production build
npm run preview      # serve dist/
```

Requires Node ≥ 22.18 (the snapshot script uses Node's built-in TypeScript stripping).

## How the data works

1. `npm run snapshot` fetches the public profile, repositories and per-repo language bytes from the GitHub REST API into `src/data/github-snapshot.json`. If GitHub fails, the existing snapshot is kept.
2. The site renders that snapshot immediately, then refreshes the profile and repositories from the API in the browser (2 unauthenticated requests).
3. If the refresh fails (network, timeout or rate limit), the snapshot stays on screen and a notice with a **Retry** button explains why. With no snapshot at all, an error panel is shown instead.

No token is ever used in the browser. In CI, `GITHUB_TOKEN` is used only by the build-time snapshot step.

Dev-only failure simulation: append `?gh=offline`, `?gh=ratelimit`, `?gh=nosnapshot` or `?gh=empty` to the dev-server URL.

## Customize

Everything GitHub can't verify lives in **`src/config/profile.ts`**. Empty fields hide their UI; nothing is invented to fill them.

| Field | Effect |
|---|---|
| `role`, `tagline` | Hero subtitle and statement (the fallback uses only GitHub facts) |
| `about` | About paragraphs (fallback: GitHub bio, then factual sentences) |
| `skills` | Self-declared skill groups, shown next to GitHub-detected languages |
| `journey` | Experience / education entries, marked "self-reported" |
| `contact.email`, `contact.linkedin`, `contact.links` | Extra contact channels (GitHub is always shown) |
| `projects.featured` | Repo names to feature, **in display order**; the remaining slots fill by stars, then recent activity |
| `projects.hidden` | Repos never shown |
| `projects.limit` | Max project cards (default 6) |
| `projects.descriptions` | Your own copy for a repo, shown with an "author note" marker |

Design tokens (colours, fonts) are at the top of `src/index.css`. Meta/Open Graph text is in `index.html`; the OG image is `public/og.png` (1200×630).

```
src/
  config/profile.ts        editable, unverifiable details
  data/github-snapshot.json  generated by `npm run snapshot`
  lib/github.ts            API fetch, normalization, project selection, language share
  lib/useGitHubData.ts     snapshot → live refresh, error and rate-limit states
  components/              Nav, Hero, Projects, Sections (About, Skills, Journey, Contact, Footer)
scripts/fetch-github.ts    build-time snapshot
```

## Deploy to GitHub Pages

The workflow `.github/workflows/deploy.yml` builds and deploys `dist/` on every push to `main`, on manual dispatch and weekly (to refresh GitHub data).

1. Create a GitHub repository (e.g. `portfolio`) and push this project to its `main` branch.
2. In the repository, go to **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. The base path is resolved automatically: `/<repo>/` for a project site, or `/` if the repository is named `QTrieu0610.github.io`. `VITE_SITE_URL` (canonical + OG URLs) is derived the same way. Locally it comes from `.env`.
